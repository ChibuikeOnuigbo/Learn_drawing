# 2D animation

Use for motion graphics, educational explainers, simple character acting, animatics, stroke reveals and layered illustration. Read [drawing](../drawing/SKILL.md) and [composition](../composition/SKILL.md) before designing a character shot.

## Exact timeline contract

- `fps`: 1–60; `frames`: total count; duration is `frames / fps`.
- Rendered indices are `0` through `frames-1`.
- Layer visibility is `[start,end)`. A layer ending at 24 is absent on frame 24.
- A key at `frames` can define the endpoint of a transition even though that frame is not rendered.
- Easing belongs to the destination key and controls motion **into** it.
- Values hold before the first key and after the last key.
- Tracks: `x`, `y`, `scale`, `scale_x`, `scale_y`, `rotation`, `opacity`, `reveal`.
- Easing: `linear`, `ease_in`, `ease_out`, `smooth`, `hold`.
- Key indices must be strictly increasing; no duplicate property tracks.
- Dimensions must be even. Colors are `#rrggbb` or `none`.

At 24 fps: anticipation frames 0–7, action 8–15, contact 16, settle 17–29, hold 30–47. Adjust to the action; these are not universal timing rules.

## Performance workflow

1. Define the action in one sentence and identify its strongest pose.
2. Block key poses: start, anticipation, extreme/contact, recovery.
3. Check arcs and spacing. Wider spacing reads faster; clustered spacing reads slower.
4. Add overlap/follow-through on loose parts after the main action works.
5. Use moving holds rather than unintended frozen footage. A deliberate hold can be powerful.
6. Preserve volume during squash/stretch unless the style intentionally breaks it.
7. Preview boundary frames, render a proof, inspect motion, then increase quality.

Do not use `smooth` everywhere by default. An impact needs appropriate acceleration and a clear contact; a mechanical conveyor may need linear motion; a pose change may need a hold.

## Minimal bouncing-ball scene

Use `templates/scene-2d.json`. It contains a floor, shadow and ball with separate X/Y and scale tracks. The important pattern is:

```json
{"property":"y","keys":[
  {"frame":0,"value":48},
  {"frame":12,"value":133,"easing":"ease_in"},
  {"frame":23,"value":70,"easing":"ease_out"}
]}
```

The ball accelerates toward contact and decelerates upward. Squash happens at contact, not randomly throughout the arc. Inspect the actual template before changing several variables at once.

## Character and asset options

Native `group` layers provide hierarchical transforms and inherited visibility. Declare a parent before its children. Parent eyes to head, hands to arms and props to an explicit attachment group. Independent X/Y scale supports blinks and squash.

For a more expressive cut-out, author nested SVG pivots and rasterize distinct poses. `src/animation_mcp/character.py` is a working example, not a universal character generator. Use an image asset `rig-frames/%04d.png` with zero-based, four-digit frame files. All required frames must exist. The full example is regenerated by `python scripts/build_showcase.py --stage author` before `--stage 2d`.

A single raster plate can move, rotate and fade, but cannot articulate hidden limbs. Do not describe that as a rigged performance. Separate plates enable parallax; genuine pose changes require separate drawings or a deformable rig.

## Stroke reveal and typography

`reveal` trims a polyline by actual length. Keep the path open and unfilled while drawing on. At full reveal, a closed path may fill. This is not fill morphing or automatic handwriting recognition.

Text is escaped, single-line, center-anchored vector text using bundled fonts. Use one layer per line, short phrases and readable holds. The 2D renderer does not auto-wrap text or generate captions; use the edit tool for wrapped timed captions.

## Tools and local commands

MCP sequence: `get_scene_schema(kind="2d")` → `save_scene` → `preview_frame` at storytelling keys → `render_scene` → `inspect_video` at exact boundaries.

CLI, with paths relative to the chosen workspace:

```bash
animation-studio render templates/scene-2d.json --output output/2d-proof --workspace .
animation-studio inspect output/2d-proof/video.mp4 --output output/2d-inspection
```

`render_scene` accepts a workspace-relative scene path. Local Python `render(scene_path, output, asset_root)` can use the scene's folder as asset root; the CLI exposes this through `--workspace`.

## Sound and limits

`scene.audio` muxes one local track. Longer audio is rejected; shorter audio is padded. It does not align phonemes, mix multiple stems or generate captions. Prepare a mix and use [video-editing](../video-editing/SKILL.md) for multi-shot assembly.

There is no mesh deformation, automatic inbetween drawing, lip sync or particle simulator in the native schema. Explicit layers/keys can author many effects; unsupported techniques need original pose assets or an external application.

## Acceptance

Check pose readability, connected joints, arcs, spacing, holds, layer visibility, text legibility, audio duration and export metadata. Technical pass is not artistic approval. Preserve scene JSON/SVG and pose sources alongside the final video.
